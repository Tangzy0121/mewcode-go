# 代码由 AI 实现，架构与审计由人负责

2026-10-02

v0 失败的直接原因是**代码由 AI 在一个冲刺里写完，人没有读**（两个 commit 均为 `Co-Authored-By: Claude`），而本项目的首要目标是学习、其次是为求职积累能经得住追问的作品。因此本轮沿用"AI 实现"（换回速度），但把"我会检查"这句不可证伪的话，换成**每章必须留下的三类审计证据**，至少各一条：

- **解释**：不合上代码，用自己的话讲清该章的数据流；
- **改动**：亲手改一个需求（加一个工具／换一个 provider／调一个上限值），并能先预测结果再运行；
- **抓错**：记录至少一处 AI 的错误或被否掉的方案。

审计证据写入 `docs/review/<chapter>.md`，与代码同为交付物。完成定义（DoD）相应收紧为三条同时成立、缺一不算完成：**每章落地 + 每章一条真机证据 + 每章一条分歧笔记**；没有真机证据的工作记为 0 分，单测通过不能顶替。

## Considered Options

- **人逐行手写**：最有利于学习，但按每周约 3.5 小时的预算会把 v1.0 推到半年以上。
- **AI 全写，章末仅验收**：这正是 v0 的失败模式，未选。
- **AI 实现 + 人架构 + 人审计（选它）**：牺牲"每一行都是我写的"，换取可在面试中被追问的审计产物。

## Consequences

- 我的角色是**架构决策者与审计者**，不是逐行作者；简历口径相应写成"设计并审计了一个 AI 协作开发的 agent harness"，而不是"我实现了 X"。
- 一次会话的产出固定为：1 章教程 → 1 条真机证据 → 1 条分歧笔记 → 1 次理解检查。
- 失败模式是"审计退化为签字"，因此 DoD 里的**真机证据**是唯一不依赖自我报告的判据。
